A guide for every building block.

Imports, states, variants and keyboard behavior — with HTML you can take into your own project.

Import a component package

Use <script type="module" src="./components/page.js"></script> for a complete page. It supplies styles, registers card/dialog tags and enhances native HTML automatically, including later insertions.

Each recipe below includes its smaller component import. Card and dialog use native slots; other packages enhance ordinary semantic HTML. Application-specific save handlers stay in your application.

Slots and reusable tags · Manual loading alternative · Open the starter

Reuse HTML with native slots

Use <tvw-card> or <tvw-dialog> and put your own HTML into their heading, content and action slots. Their modules include registration, templates, styles and behavior. More instances reuse the same import.

Buttons & icons

Variants
Primary, secondary, quiet, danger; small, default, large, icon-only.
States
Default, hover, focus, disabled, busy.
Use & keyboard
Enter/Space activates a button. Give icon-only buttons an accessible name. Use links for navigation.
Import
components/buttons.js — styles and behavior included
Copyable example
<script type="module" src="./components/buttons.js"></script>
<button class="tvw-button" type="button">Save changes</button>
<button class="tvw-button tvw-button--secondary" type="button">Cancel</button>

Inputs & choices

Variants
Text, email, date/time, range, textarea, checkbox, radio, switch and segmented radio groups.
States
Empty, populated, required, readonly, disabled, invalid; labels remain visible.
Use & keyboard
Use visible labels, fieldset/legend for related choices, and aria-describedby for help. Native keys and validation remain available.
Import

Copyable example

  <input class="tvw-input" id="email" name="email" type="email" required aria-describedby="email-help">
  <small class="tvw-help" id="email-help">Use your work address.</small>
</div>

Form validation

Variants
Native constraints, custom errors, asynchronous validation and cross-field rules.
States
Unsubmitted, invalid, validating, valid, service unavailable. Values survive failures.
Use & keyboard
Submit focuses a linked error summary. Correcting an input cancels stale checks. Server messages are text.
Import

Menus, popovers & tooltips

Foundations & content

Use semantic tokens for colors, spacing and typography. Keep action labels specific: “Save project” rather than “OK”. Describe errors with a problem and a recovery action. Use heading levels to express structure, and text alongside status colors.
