Get started

01 / Foundation

Copy css/timvw.css into your project and add class="tvw" to the body. For interactive components, copy the runtime js/ directory and call init(). For selective loading, use css/foundation.css plus the required CSS parts and direct module imports. See the import guide or download the runtime bundle.

No package install or build step. Serve your files over HTTP to use JavaScript modules; the HTML and CSS also work directly from disk.

View source
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My project · timvw</title>
  <link rel="stylesheet" href="./css/timvw.css">
</head>
<body class="tvw">
  <main class="tvw-card">
    <h1>Hello, timvw.</h1>
    <p>Your next project starts with HTML.</p>
    <button class="tvw-button" type="button">A native button</button>
  </main>
  <script type="module">
    import { init } from './js/timvw.js';
    init();
  </script>
</body>
</html>

Tabs

HTML + CSS + JS

Arrow keys change tabs; Home and End jump to the first and last. Without JavaScript, all sections stay readable.

Overview

Related content, one section at a time. The selected tab and its panel are linked for assistive technology.

Usage

Give every button and panel a unique ID, then call init() after the markup is available.

Keyboard

Use Left and Right, Home, or End to select a tab. Tab moves into the selected panel.

View source
<div class="tvw-tabs" data-tvw-tabs>
  <div data-tvw-tablist aria-label="Component details" hidden>
    <button type="button" id="tab-overview" aria-controls="panel-overview">Overview</button>
    <button type="button" id="tab-usage" aria-controls="panel-usage">Usage</button>
    <button type="button" id="tab-keyboard" aria-controls="panel-keyboard">Keyboard</button>
  </div>

Accessibility is part of the markup.

The components provide visible focus styles, native controls, and keyboard behavior for tabs and dialogs. Your content and integration still need testing.

  • Use a logical heading order and visible, descriptive labels.
  • Keep errors understandable without relying on color.
  • Test every interaction with only a keyboard and with your target screen readers.
  • Check your custom colors, zoomed layouts, and narrow screens.
  • Keep essential content available when JavaScript cannot load.

This is an initial release, not an accessibility certification. See the contribution guide for the review checklist.
